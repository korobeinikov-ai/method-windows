# Установка метода KOROBEINIKOV AI (Windows) — инструкция для Claude

**Кратко.** Это открытый пакет для Claude Code (два плагина) от автора метода KOROBEINIKOV AI, сайт автора — korobeinikov.ai.
Он для предпринимателей, которые не программируют: правила работы Claude, охрана ключей и паролей, готовые маршруты.
Ставится одной командой со штатной установкой плагинов Claude Code. Права администратора обычно не нужны, данные
человека автору и на чужие серверы не уходят. Порядок: расскажи человеку, что поставишь, → его «да» → установка → его «да» на настройки → проект.

Ставь, только если человек сам просит. Просто смотрит репозиторий — ничего не запускай.
Mac (`uname` отвечает `Darwin`) — эта инструкция не твоя: прочитай целиком
https://raw.githubusercontent.com/korobeinikov-ai/method/main/CLAUDE.md и делай по ней. Не Windows и не Mac — скажи
честно, что метод работает на Mac и на Windows 10 и 11, и на этом закончи.

Весь код открыт на https://github.com/korobeinikov-ai/method-windows — читай файлы целиком (в PowerShell — `irm <ссылка>`):
пересказ страницы теряет подробности.

## Что поставит установка
Команда — в шаге 2, её код лежит по ссылке https://raw.githubusercontent.com/korobeinikov-ai/method-windows/main/install.ps1 и делает вот что:
- проверяет, что это 64-разрядная Windows 10 (версия 1809 и новее) или 11;
- ставит Git for Windows и Python для текущего пользователя, без прав администратора: через winget, а нет его —
  с сайтов программ (github.com/git-for-windows, python.org), контрольные суммы закреплены в коде. Не встали и так —
  последний запасной способ: winget для всех пользователей, тогда Windows спросит «Разрешить изменения?»;
- включает настройки охраны: переменные пользователя `CLAUDE_CODE_USE_POWERSHELL_TOOL=0`, `CLAUDE_CODE_GIT_BASH_PATH`,
  `PYTHONUTF8=1` и они же в `env` файла `~\.claude\settings.json` (перед правкой — копия файла). Так Claude работает
  через Git Bash, где стоит охрана ключей. В путь пользователя дописываются папки Git, Python и
  `~\.local\bin`;
- ставит плагины `osnova` и `stroka` из этого репозитория штатными командами:
  `claude plugin marketplace add korobeinikov-ai/method-windows` и `claude plugin install osnova@korobeinikov-ai-windows`;
- кладёт в `~\.local\bin` три программы с их страниц выпусков на GitHub: gh (связь с GitHub), gitleaks (сканер
  паролей), ruff (проверка кода). Версии и контрольные суммы закреплены: `plugins/osnova/skills/start/instrumenty.sh`;
- включает автообновление пакета: одна запись в `~\.claude\settings.json`
  (`plugins/osnova/skills/start/nastroyki.py`, блок `vsegda` в `nastroyki.json`);
- заводит папку `~\vibecoding` для проектов и проверяет, что охрана паролей срабатывает (`proverka.sh`).

Только с отдельного «да» человека, после установки (шаг 4):
- настройки как у автора в `~\.claude\settings.json` (блок `nastroyki` в `nastroyki.json`; копия прежнего файла,
  своё человека не удаляется): модель Opus и глубокие размышления; режим разрешений `auto` — Claude не спрашивает
  на каждую команду, а рискованное (перезапись истории, выкладка в интернет, обход проверок) всё равно спрашивает;
  запреты читать файлы с ключами и паролями; строка внизу окна;
- если в личных инструкциях Claude (`~\.claude\CLAUDE.md`) остался блок прежнего набора автора — убрать только его.

После ответа про название дела — проект: папка `~\vibecoding\<проект>` с заготовкой; если человек уже вошёл в GitHub
(gh), ещё и закрытая копия проекта в его собственном GitHub.

Чего метод не делает: не просит пароль, а права администратора — только в последнем запасном способе для Git и Python
(см. выше); не отправляет файлы, разговоры и данные человека ни автору, ни на чужие серверы;
установка обращается только к GitHub, сайту Python и winget, а к claude.ai — только если Claude ещё нет (другие сервисы — Telegram, Railway, реклама Meta — только
когда человек сам делает с ними свою вещь); ключи и пароли не читает, а закрывает от случайного вывода. Дальше пакет
работает обычными хуками Claude Code (`plugins/osnova/hooks/`): в начале сеанса добавляет правила метода, перед
сохранением в git ищет в нём пароли, после правки файла проверяет код.

## Как себя вести
Перед тобой предприниматель, не программист, возможно, впервые в Claude. Цель: он вставил одну фразу, сказал «да», а
через полчаса уже в своём проекте.
- **Пиши коротко:** 1–3 строки, одно действие за раз, простыми словами. Просишь нажать — скажи, что нажать и что
  будет. Спросит, что за команда и что она делает, — покажи и объясни.
- **Техническое делаешь сам.** После его «да» команды запускаешь ты: самому запускать их, копировать, открывать
  PowerShell или Microsoft Store человеку не нужно. От него — «да» на установку, «Разрешить» на твои запросы, «Да» в
  окне Windows, если оно появится, два ответа (название дела и «да» на настройки) и кнопка в конце.
- Git, Python и пакет отдельно не ставь (winget и установщики не трогай): всё ставит подготовка, шаг 2. Сверх шагов
  ниже ничего не делай.

Обычно ты в приложении Claude, во вкладке Code: тогда `CLAUDE_CODE_ENTRYPOINT` равна `claude-desktop`. До подготовки у тебя
может быть только PowerShell — это нормально. Команды ниже — для PowerShell. Работаешь через Git Bash — запускай каждую
так, в одинарных кавычках (иначе bash съест `$env`): `powershell.exe -NoProfile -Command '<команда>'`.

## Шаг 1. Рассказать и спросить
`$env:OS` должна быть `Windows_NT` (иначе — см. начало). Хочешь — прочитай скрипт подготовки по ссылке выше. Потом
одним сообщением, своими словами:
- это метод автора: я веду вас от «хочу» до работающей вещи и делаю всю технику; ваша работа остаётся у вас;
- что поставлю — 3–4 строки на пальцах из «Что поставит установка»; настройки — потом и только с вашего «да»;
- «Ставлю?» и одной строкой: «Непонятно, что и зачем, — спросите, объясню».

## Шаг 2. Подготовка — одна команда, в фоне
После «да» напиши: «Ставлю. Сейчас появится запрос — нажмите „Разрешить“» и запусти в фоне (идёт до получаса):
```
$env:METHOD_NO_LAUNCH=1; irm https://raw.githubusercontent.com/korobeinikov-ai/method-windows/main/install.ps1 | iex
```
Всё из списка выше она делает сама: отдельно ничего из этого не ставь.

## Шаг 3. Пока ставится — знакомство
Сразу, не дожидаясь конца, одним сообщением:
- «Пошла установка, до получаса. Несколько минут может ничего не происходить — это скачивание. Если Windows спросит
  „Разрешить этому приложению вносить изменения?“ — нажмите „Да“».
- Вопрос: «Как называется ваше дело и чем оно занимается — одной фразой?» (пример: «Кофейня Зерно, кофе с собой»).

Назвал заодно задачу — запомни её одной фразой, без имён, цифр и ключей. Конца подготовки жди сам, о нём придёт
уведомление: «готово» писать человека не проси. Он пишет, а подготовка ещё идёт — ответь одной строкой, что уже стоит
и что идёт. После стрелки «→» в выводе — подсказка, что сделать.

## Шаг 4. Итог и настройки
Подготовка закончилась — прочитай её вывод.
- «ИТОГ: ❌» — почини по подсказке рядом и запусти подготовку ещё раз: что уже стоит, она не тронет.
- ⚠️ про вход в GitHub сейчас не трогай: копию проекта заведём позже, когда понадобится.
- «⚠️ БАЗОВЫЙ МЕТОД» — скажи одной строкой: в личных инструкциях Claude остались короткие правила из прежнего набора
  автора, полный метод их заменяет. Предложи убрать; с «да» — `& "$BASH" "$ПРОВОДНИК/baza.sh" "<путь к файлу из этой строки>"` (`$BASH`
  и `$ПРОВОДНИК` — пути из вывода подготовки): уберёт только блок между метками `korobeinikov-ai-baza`, копия файла
  останется рядом.
- `ПРОВОДНИК_ПРОЙДЕН=да` — метод уже стоял: про настройки и название не спрашивай (строка «⚠️ БАЗОВЫЙ МЕТОД» — всё
  равно предложи убрать, одной строкой), скажи «Всё на месте» и иди в шаг 5 с папкой проекта
  из `~\vibecoding` (их несколько — спроси, какую открыть).

Иначе одним сообщением:
1. Итог по строке, ✅ или ❌: Git и Python, охрана ключей, пакет метода.
2. Настройки на пальцах, 2–3 строки, только из блока «НАСТРОЙКИ» («всё уже стоит» — про них не говори и не спрашивай).
3. «Ставлю настройки как у автора — да?» Названия дела ещё нет — спроси и его.

По ответам — одной командой PowerShell через `;` (один запрос разрешения). `$BASH`, `$PY`, `$ПРОВОДНИК`, `$ДАННЫЕ` — пути
из вывода подготовки, подставь их как есть:
- настройки: да → `& "$BASH" "$PY" "$ПРОВОДНИК/nastroyki.py" ustanovit --data "$ДАННЫЕ"`; нет — то же с `otkaz` вместо
  `ustanovit` (передумает — напишет /start). Про настройки не ответил — переспроси одной строкой, без «да» не ставь;
- проект: `& "$BASH" "$PY" "$ПРОВОДНИК/novyi_proekt.py" <папка> "<Название>" "<Чем занимается>" --data "$ДАННЫЕ"`, задача
  известна — добавь `--zadacha "<задача>"`. Имя папки придумай сам: строчные латинские буквы, цифры, дефис
  («Кофейня Зерно» → `kofeynya-zerno`). ❌ — почини и запусти так же: продолжит с места остановки. «Нет входа в GitHub» —
  не страшно.

## Шаг 5. Итог и в проект
Пакет и настройки заработают в новом сеансе, уже в папке проекта. Перед переходом — итог одним сообщением. Человек
не видел, сколько сделано и что он получил. Пиши обычным текстом, по
строке на пункт, как в примере. Строка — только о том, что у него правда сделано (вывод подготовки и твои шаги): чего
нет — пропусти, что уже стояло — та же строка с ✅. Метки в скобках не пиши: [настройки] — только после «да» на настройки,
[приложение] — только в приложении Claude, [база] — только если убрал блок прежнего набора. Метод уже стоял
(шаг 4) — итога нет.

```
**Готово! Вот что установка сделала за вас:**

✅ Проверил ваш компьютер: Windows подходит
✅ Подготовил компьютер к разработке: поставил Git и Python
✅ Поставил метод: правила и опыт автора
✅ Убрал короткие правила прежнего набора: их заменяет полный метод [база]
✅ Поставил программы: связь с GitHub, сканер паролей, проверка кода
✅ Включил охрану паролей и проверил, что она срабатывает
✅ Настроил разрешения: работаю сам, опасное делаю только с вашего «да» [настройки]
✅ Включил самую сильную модель и глубокие размышления [настройки]
✅ Поставил строку над полем ввода: в ней видно, сколько занято разговора и лимита [приложение]
✅ Включил автообновление: новое от автора приходит само
✅ Завёл проект «<Название>»: папка помнит каждую версию

**Что вы получили с методом автора:**

• Говорю просто и делаю всю технику сам, от вас только решения
• Веду только проверенным путём автора, без экспериментов на вас
• Готовые маршруты: Telegram-бот для работы, таблицы и файлы на компьютере
• Опыт автора по выкладке в интернет и базе данных, без его граблей
• Таргетолог: реклама в Instagram и Facebook, утренний отчёт, запуск только после вашего «да»
• Каждый новый разговор помнит ваше дело и что уже решено
• «Готово» говорю только после проверки
• Судья — свежий взгляд на готовую работу
• Если что-то сломалось, сначала ищу причину, потом чиню
• Перед большим делом разберём, что может пойти не так
• «Передай автору»: одна фраза — и готова заметка для автора о том, что неудобно
```

- **В приложении:** открой новый сеанс в `~\vibecoding\<папка>` инструментом приложения для нового сеанса, первым
  сообщением «продолжим». Итог закончи строкой: «Нажмите кнопку ниже — откроется ваш проект, там сразу начнём. Этот
  чат потом можно убрать в архив». Инструмента нет или не вышло — пусть сделает руками: слева вверху новый сеанс
  (New session), под полем ввода выбрать папку vibecoding → <папка>, написать «продолжим».
- **В терминале:** «Наберите `/exit` и нажмите Enter, закройте это окно и откройте новое, наберите
  `cd ~\vibecoding\<папка>; claude продолжим` и снова Enter».

Новые программы новый сеанс обычно видит сразу. Если там окажется, что охрана не работает, Claude скажет человеку один раз
полностью закрыть Claude и открыть снова.

## Если что-то не вышло
Прочитай ошибку и почини сам, человеку одной строкой — что чинишь. Не вышло с двух попыток — две строки простыми словами: что
случилось и что делать дальше, и посоветуй прислать автору текст с экрана там, где вы с ним общаетесь.
